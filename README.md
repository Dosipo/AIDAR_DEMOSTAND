# ИДС Трасса — Прототип диспетчерской системы (ПК0–ПК180)

Веб-прототип интеллектуальной диспетчерской системы линейного дорожного строительства, спроектированный по стандартам **Trimble B2W**, **HCSS Resource Planner** и **Infrakit Office**.

## Запуск через Docker Compose

### 1. Сборка и запуск контейнера в фоновом режиме
```bash
docker compose up -d --build
```
После сборки приложение будет доступно по адресу:
**http://localhost:3000**

### 2. Просмотр логов и статуса контейнера
```bash
docker compose ps
docker compose logs -f
```

### 3. Остановка контейнера
```bash
docker compose down
```

---

## Локальная разработка (без Docker)

```bash
npm install
npm run dev
```

## Состав экранов и контуров управления

1. **Трасса и флот (`[MAP]`)** — интерактивный срез трассы ПК000+00 – ПК180+00 с 4 технологическими слоями и выдвижным правым инспектором (Docked Inspector) для разбора телеметрии, инцидентов и подбора замены без ухода с карты.
2. **Инциденты простоя (`[INC]`)** — разделение 3 понятий простоя (остановка по GPS, холостой ход ДВС, производственный простой), временная шкала датчиков и верификация причины диспетчером.
3. **Матрица перераспределения (`[MOV]`)** — оценка кандидатов по 5 факторам ИДС, расчет плеча и потребности в низкорамном трале `ТРАЛ-01`, явная индикация `Не рассчитано` при отсутствии данных и выпуск нарядов `Move Planner`.
4. **Реестр техники (`[EQP]`)** — единая карточка машины, 3 обязательные отметки времени (`t_device`, `t_server`, `t_verified`) и разрешение конфликтов дублирования терминалов.
5. **Полевой учет (`[LOG]`)** — Side-by-Side проверка неизменяемого оригинала сводки из мессенджера/скана и редактируемого цифрового черновика с автоконтролем единиц измерения (тонны ↔ м³).
6. **План-факт и 1С (`[ERP]`)** — сопоставление сменных целей и подтвержденного факта (`Tracking Account`), переход к первоисточнику и идемпотентный шлюз выгрузки в 1С:ERP без риска дублирования проводок.
